# @hackathon-atlas/cli

Local keyword search over a SQLite FTS5 index generated by `@hackathon-atlas/catalog-index`. The index is generated. It is not the canonical catalog.

The command does not call a language model and does not use a vector database. It does not create catalog records and does not invent projects.

## Command

```text
hackathon-atlas search --index <generated.sqlite> [--filter field=value] <keywords>
```

`--filter` may be repeated. A filter is applied only when its field is a column of the generated `records` table. If the column is absent, the filter is not applied and the JSON result lists that filter as `status: "unknown"`.

`hitCounts.real` counts matching rows stored with `synthetic` false. Rows stored with `synthetic` true are counted only in `hitCounts.synthetic`. If the index has no `synthetic` column, both counts are `null` with `status: "unknown"`, and those rows are not reported as real. A stored flag is not, by itself, evidence that a row is a genuine hackathon project.

This package commits no catalog fixture. Tests build a temporary index and delete it. The catalog-index fixture it reads is labeled synthetic.

## Versions

TypeScript `7.0.2` and Vitest `5.0.2`, matching the workspace pins. The search uses Node's built-in `node:sqlite`. It does not add `better-sqlite3`.

From the repository root, with Node 24.21.0:

```text
pnpm install --frozen-lockfile
pnpm --filter @hackathon-atlas/cli typecheck
pnpm --filter @hackathon-atlas/cli test
```

`pnpm test` at the root also runs this package because `packages/*` is a workspace glob.
